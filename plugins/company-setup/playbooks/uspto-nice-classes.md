# USPTO Nice Classification — choosing trademark classes for company formation

**Purpose:** Pick the trademark classes a candidate name should be cleared against, based on what the business actually does. Decide for the user; don't make them learn Nice Classification.

**Source:** WIPO Nice Classification (NCL 12-2025), USPTO ID Manual.

---

## What classes are

USPTO splits trademark coverage into **45 classes** — an international system. Trademark rights only apply *within the classes you file in*. "SOLIDUS" for shoes (Class 25) doesn't conflict with "SOLIDUS" for software (Class 42).

- **Classes 1–34** — goods (physical products)
- **Classes 35–45** — services

When checking name availability, scope the search to the classes the founder would actually file in. Otherwise you flood the report with irrelevant "SOLIDUS" filings for shoes, chemicals, packaging, etc.

## How a class is decided (USPTO mechanics)

1. The applicant writes a description of goods/services
2. The USPTO ID Manual contains pre-approved descriptions, each tagged with its class. https://idm.uspto.gov/
3. If the applicant uses a pre-approved description, the class is automatic
4. If they write a custom description, the examining attorney assigns the class
5. A single application can cover multiple classes — each adds ~$350 (TEAS Plus per-class fee, 2026)

## Strategic-narrowing tactics

When a candidate is blocked in one of the target classes but clean in another, the agent can suggest:

- **File in the clean class only**, with a narrow goods/services description that explicitly excludes the conflicting domain. Example: file in Class 42 with description "IT consulting services in the field of *non-fintech* technology operations" — that narrow scope distinguishes you from a fintech-focused Class 42 holder like Solidus Labs.
- **File a different mark for the blocked class** (e.g., a brand sub-name) and keep the master mark for the clean class.
- **Operate without federal TM**, file the state LLC, build common-law usage in your geography, revisit federal filing once you have demonstrated commerce. Cheaper but riskier.

When a candidate is blocked in *both* primary classes, there's no narrow-path workaround. Recommend a different name.

---

## Default decisions if context is genuinely unclear

If the agent can't infer the archetype from conversation context and the user can't articulate it, the safe default is:

- **For any service-business name check:** `--class 35,42` (covers consulting + tech, the two most common service classes for new LLCs)
- **For any product-business name check:** include the appropriate goods class plus Class 35 (retail services)
- **For no-info "just check it" requests:** run with no class filter — slower, more results, but no false-clear

Always announce the chosen classes and the reasoning in one line before running. Allow override.
